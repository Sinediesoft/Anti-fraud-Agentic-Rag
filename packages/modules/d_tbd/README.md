## 一句話

**「賣貨便詐騙偵測器」：你貼一段可疑的交易對話進來，它告訴你對方要你做的哪一步
是官方明文說過不存在的、你走到第幾步、接下來 30 分鐘該做什麼——每一條都標出
是哪個機關、哪一天說的。**

### 手法長什麼樣（官方版本，不是我推的）

內政部警政署刑事警察局公告〈賣貨便需要實名認證？！千萬別信假客服〉
（發布 115-05-17，更新 115-05-18）把整條鏈寫出來了：

> 歹徒於 Facebook、Threads、Instagram、Dcard 鎖定買／賣家，或假意以送東西名義接觸，
> 傳送**偽冒 7-11 賣貨便或全家好賣+** 之網站，要求用指定賣場寄送貨物。民眾操作假網站後
> 立即跳出「**未完成金流簽署**」「**需實名制認證**」，隨後引導聯繫假客服；假客服再指示
> 開啟**無卡提款**、操作轉帳及誘騙**翻拍 QR Code 付款碼**。

公告同時列出七條防詐要點，其中第三條就是這個模組的地基：

> **「賣貨便無需實名認證、金流簽署。」**

這句話由刑事局自己寫成公告標題，不是我從語料反推的。**這個題目最大的風險已經消除。**

| 付了錢東西沒寄到、賣家跑掉、貨不對版 | 不是 D | 那是純粹的網購糾紛，沒有假客服這一棒 |

> **給 E 的提醒（這條對你有用）**：我實測「交貨便」「店到店」這兩個詞的區辨力是
> **−0.35 和 −0.10**，也就是它們在**你的**人頭帳戶案子裡出現得比在我的案子裡更頻繁
> ——因為「寄提款卡給詐騙集團」大量使用超商店到店。所以我會把這兩個詞留在
> `platform_terms`（切語料要用），但**絕對不放進 `route_terms`**，免得路由把你的案子搶過來。

> **給 B（shin5shin）**：`team.yml` 裡你的 platform／tactic 還是 TODO。
> 我佔的是「超商物流 × 假客服」，麻煩避開網購交易與賣家方向，或是我們直接談界線。

## 行動劇本的六個階段

`playbook.yaml` 會照這個切。**第一條行動刻意跟其他四組不同**：A／C／E 的第一條
多半是「撥打 165」，我的是「**立刻停止操作**」——因為我的使用者是
**交易進行到一半被打斷的人**，他此刻通常還沒有損失，時間差就是這個模組的價值。

| 階段 | 風險 | 第一條行動 |
|---|---|---|
| S1 剛被要求用賣貨便交易 | medium | 確認：官方流程雙方都不需要另外「認證」 |
| S2 已建賣場／已點連結 | medium | 不要再往下點，從官方 APP 重新進入查證 |
| S3 被說認證失敗／未開通 | **high** | **立刻停止操作，你還沒有損失** |
| S4 已加假客服／假專員 | **high** | 掛電話、封鎖前先截圖存證；真客服不會開視訊 |
| S5 已操作／已轉帳 | **critical** | 立即撥 165 並聯繫銀行圈存 |
| S6 被要求第二筆 | **critical** | 那筆「解凍金」是同一組人，不要匯 |

## 我刻意不做的事

**不判定對方是不是詐騙犯。** 判斷意圖是司法認定，誤判代價很高（把正常買家說成詐騙犯）。

| 說 | 不說 |
|---|---|
| 「刑事局 115-05-17 公告：賣貨便無需實名認證」 | 「這個人是詐騙犯」 |
| 「命中 4 項可觀察條件」 | 「這是詐騙，信心 87%」 |
| 「這個網域不是官方網域」 | 「對方想騙你的錢」 |

每次輸出都會附：**本系統不判定對方是否構成詐欺，以上為可觀察條件的命中結果。**

Demo 時我會特別放一題**正常買家**（「我想買這個，可以用賣貨便寄到台中嗎」），
證明系統不是看到「賣貨便」就喊詐騙。說明書規定的九項指標照跑，我另外自己加兩項：
**正常交易誤報率 < 15%**、**依據可驗證率 100%**（每條 `legal_refs` 都要連得到真實公告與日期）。

## 誠實揭露（三件我不想等到第七週才講的事）

**一、我引用的筆數是我自己抓的，不是全隊語料。**
我在 2026-09-21 自己抓了 165 的 194,355 筆跑本機腳本，量到
`total_cases` 62,395、`platform_cases` 13,046（20.9%），其中 11,389 筆命中完整的假客服鏈、
93% 命中 ≥3 條訊號。**但這不是 S6 的交叉表。**
`pack.yaml` 的 `stats` 與 `labels_canon` 我會等全隊語料抓完、用同一份 `corpus.parquet`
重新量過才填——不同源的數字沒辦法互相比較。在那之前 `labels_canon` 留空、
`is_configured` 為 False，模組載得起來但不會搶案子（跟 E 現在的狀態一樣）。

**二、165 公開的是抽樣，不能拿來做趨勢統計。**
刑事局 2026/1–2 月網購詐騙報案 6,735 件，我的語料同期只有 3,494 筆，約三分之一。
所以語料的月份起伏反映的是 165 的公開節奏，不是案件真實增減。
**我第一版寫的「2026 年下降 69%」是錯的，已經刪掉。** 真實情況是刑事局 2026-03 還在發統計、
2026-05 還在發公告，這個詐騙正在高峰。

**三、系統救不了所有人。**
86% 的受害者是轉帳後才報案的，這個模組真正能阻止的是 S1–S4 以及 S6 的第二筆。
另外 40.3% 的受害者當下就覺得怪了——**所以價值不在「幫你看出這是詐騙」**，
而是在你被情緒勒索與時間壓力逼著操作的當下，給你一句有機關、有日期、可查證的話，
讓你有理由停下來。刑事局公告裡描述的情緒勒索（假買賣家同時訊息轟炸，
稱小孩急需開刀、老公家暴）在語料裡幾乎測不到——受害者報案時講的是錢怎麼沒的，
不會描述當時的心理壓迫。**這一軸只能從官方公告進系統，不能從語料學，
這正好是 `knowledge_refs` 的用處。**

## 怎麼建立這個模組（原佔位說明，留著備查）

```bash
cp -r packages/modules/_template/* packages/modules/d_tbd/
```

然後改 `pack.yaml`（id 要跟資料夾名一致）、`playbook.yaml`、`module.py` 的類別名稱。
資料夾之後會改名成 `d_<平台>_<手法>`，那時要同步 `.github/team.yml` 與 `.github/CODEOWNERS`。

規矩：這個資料夾只有我能改（見 `.github/CODEOWNERS`），別人動到會被機器人擋下來。
