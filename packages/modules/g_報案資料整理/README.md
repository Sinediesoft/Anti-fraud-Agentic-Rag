# g：報案資料整理（demo，尚未認領）

> 提案見 #48 第 3 項。這是 demo，還沒接進產品。

## 這是什麼

使用者把自己的報案資料（報案人、經過、每一筆付款、對方聯絡方式、保存的證據）
填進一份 YAML，工具整理成一份 Markdown，並列出「還缺的資料」——例如某一筆
轉帳沒寫收款帳號，或是沒列出保存的證據。可以選擇附上系統判讀（`Verdict` JSON），
文件會帶上詐騙類型與目前階段。

它不做新的判讀，只負責把使用者提供的事實整理好。

## 定位：報案前的資料準備，不是報案書

向警察報案**沒有「民眾自己寫的正式報案書」**（2026-09-28 查證）：

- 正式紀錄是警察在派出所製作的**筆錄**，完成後會拿到「**受（處）理案件證明單**」
- 只打 165 或只做網路報案**不算完成報案**，要拿到證明單才算——產出的文件開頭會提醒這一點
- 官方建議報案時準備的東西：匯款／轉帳紀錄、對話截圖、詐騙網址、對方名稱或帳號、
  發生時間與經過、金額與付款方式——正是這份文件整理的內容

最接近的官方入口是 165 全民防騙網的「我要報案」：先用筆錄預製系統做初步範本，
再轉介到派出所完成筆錄。**還沒對照過那張表單的欄位**，將來要對接的話得先看過。

真正有正式格式的是向地檢署提告用的**刑事告訴狀**（司法院與各地檢署有官方例稿）。
那是法律文書，不在這個工具的範圍內。

出處：[臺北市政府警察局防制詐騙專區](https://md-fraud.police.gov.taipei/cp.aspx?n=CD9002B9355919D1)、
[刑事警察局常見問答](https://www.cib.npa.gov.tw/ch/app/faq/view?module=faq&id=18233&serno=8306e5f3-6b7a-45e9-9d21-af24d4fac9af)、
[165 全民防騙網](https://165.npa.gov.tw/)、[司法院書狀範例](https://www.judicial.gov.tw/tw/lp-1370-1.html)

## 跟系統其他地方方向相反的一點

其他模組拿到原文，第一件事是過 `shared.deid`：金額換成範圍、帳號遮掉。
但報案需要的正是**精確金額與完整帳號**，而 `Verdict` 刻意沒有保留這些
（見 `CaseProfile.amount_range`：「不放精確金額」）。

所以這個工具：

- 資料由使用者直接提供，不從 `Verdict` 反推
- **不過 deid，也不呼叫任何模型**——純範本，全程在本機
- 文件結尾提醒：含真實個資，不要上傳，也不要傳給自稱能幫你追回款項的人

## 用法

```bash
python -m packages.modules.g_報案書_擬稿.cli packages/modules/g_報案書_擬稿/examples/facts.example.yaml --out ../報案資料整理.md
```

- 格式見 [`examples/facts.example.yaml`](examples/facts.example.yaml)（全是假資料）
- `--verdict <verdict.json>` 可選，附上系統判讀
- `--out` 必填。**不要寫在 repo 裡**——產出含真名與完整帳號

## 「還缺的資料」檢查什麼

| 條件 | 提醒 |
|---|---|
| 某筆付款沒填時間 | 第 N 筆付款缺時間 |
| 轉帳、ATM、網路銀行、超商代碼、虛擬貨幣沒填收款資訊 | 第 N 筆付款缺收款資訊 |
| 沒有對方聯絡方式 | 沒有對方的聯絡方式 |
| 沒有列出證據 | 沒有列出保存的證據 |

「第 N 筆」跟付款表格的列號一致：付款照時間排序，沒填時間的排最後。

## 為什麼沒有 `pack.yaml`

跟 `f_合約_違法比對` 同一個理由：沒有 `pack.yaml`，`app/registry.py` 就不會載入，
不會跟 A–E 搶 `can_handle()`；放在 `packages/modules/` 底下，則可以讓
`tools/check_boundaries.py` 一起掃。
