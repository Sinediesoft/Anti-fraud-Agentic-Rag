# 怎麼新增第六個模組

> 這一節是把專題變成產品的證明（說明書 S23 第 5 點）。
> 這個架構最重要的性質是：**加一個模組很便宜 —— 外殼一行都不用改。**

## 要動什麼

```bash
cp -r packages/modules/_template packages/modules/f_<平台>_<手法>
```

然後只改這個新資料夾裡的東西：

| 檔案 | 改什麼 |
|---|---|
| `pack.yaml` | `id`（要跟資料夾名一致）、`code`、`name`、`platform`、`tactic`、標籤與關鍵詞、`knowledge_refs`、`thresholds` |
| `playbook.yaml` | 這一類的階段與行動清單。第一條行動要跟其他模組明顯不同 |
| `module.py` | 類別名稱 |
| `m1`~`m5` | 自己的做法 |
| `eval/route_questions.yaml` | 20 題白話考題 |

repo 層級只要再加兩行：`.github/CODEOWNERS` 與 `.github/team.yml` 的路徑。

## 不用動什麼

- `app/` 外殼 —— **一行都不用改**。開機掃描時新資料夾會被自動載入
- `packages/contracts/` 介面規格
- `packages/shared/` 共用三樣

## 候選清單（說明書 §0.2）

做完 A–E 五個之後，接著可以加：

| 手法 | 案件數 |
|---|---|
| 色情應召詐財 | 11,746 |
| 虛擬遊戲詐騙 | 5,276 |
| 盜用 LINE 帳號 | 3,581 |

八到九個模組就能涵蓋九成語料。每加一個的成本，
就是一個人再做一次說明書的階段三（S9–S15）。
