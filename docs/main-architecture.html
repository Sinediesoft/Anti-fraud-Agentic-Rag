裝置與記憶體的細節

  • GPU（C 的生成、E 的空呼叫）：qwen2.5:3b Q4_K_M 跑在 Ollama 自己的行程，不在 Python 裡；第一次呼叫才載入，閒置 5 分鐘自動卸載。A 的 Mac（M5）是 Metal＋統一記憶體，ollama ps 顯示 2.4 GB、100% GPU。B、C 的 GTX 1650 是 CUDA＋4 GB 顯卡記憶體，實測約 2.3 GB、100% GPU。D 的筆電沒有獨顯，Ollama 改裝在教室電腦（1050 Ti，4 GB，還沒實測）；沒有 GPU 的機器，Ollama 會退回 CPU 跑。E 的 5070 Ti 有 16 GB，但全隊用同一個 3B 模型；num_ctx 一律鎖 8192。
  • CPU（bge-m3、OCR）：五台都一樣。bge-m3 寫死 cpu＋fp32，分數才能互比（實測參數在 cpu、float32）；OCR 的 onnxruntime 實測只開 CPUExecutionProvider。兩者都在 Streamlit 的 Python 行程裡，載一次共用：bge-m3 約 2.2 GB；OCR 模型檔約 32 MB，跑圖時行程記憶體會長到約 1.5 GB。
  • 不在查詢路徑上：重排序 bge-reranker-v2-m3（rerank() 還沒實作，決議只用在評估）；雲端模型（沒有任何地方呼叫 call_cloud()）。
